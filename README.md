# Разбор входящих заявок

Менеджер вставляет обращение клиента и получает тему и черновик ответа. Если AI не справился, страница предлагает ручной разбор и убирает старый черновик. Исходный текст остаётся в поле.

## Запуск

Нужен Node.js 20 или новее. Устанавливать зависимости не нужно.

```sh
node server.mjs
```

Открыть http://127.0.0.1:3000. Другой порт:

```sh
PORT=3001 node server.mjs
```

## Тесты

```sh
node --test
```

Тесты поднимают сервер на свободном порту и отправляют настоящие HTTP-запросы. Проверяются пустой и неверный ввод, корректные ответы, все пять сбоев имитатора, структура JSON и таймаут. Отдельный тест проверяет провайдера, который игнорирует отмену: ответ всё равно должен прийти примерно за 300 мс.

## API

`POST /api/triage`, JSON с полем `text`:

```json
{"text":"Когда будет доставка?"}
```

| Ситуация | HTTP | Ответ |
| --- | --- | --- |
| Непустая строка, корректный ответ AI | 200 | `{"status":"ready","topic":"delivery","draft":"..."}` |
| Пустой или нестроковый text, отсутствующее поле, битый JSON | 400 | `{"status":"invalid_input"}` |
| Ошибка AI, таймаут или некорректный результат | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

В `app.mjs` результат модели сначала разбирается как JSON, затем проверяются тема (`delivery`, `pricing`, `other`) и непустой строковый черновик. Ответ собирается из этих полей явно, лишние поля модели в API не попадают.

На модель отведено 300 мс. `Promise.race` ограничивает ожидание, `AbortController` отменяет работу имитатора, таймер очищается в `finally`. Если реальный провайдер проигнорирует отмену, его работа может продолжиться, но API её уже не ждёт. Выданный `mock-ai.mjs` не изменён.

## Проверка страницы

1. Отправить пустой текст или пробелы: появится подсказка, запроса к API не будет.
2. Ввести «Когда доставка?»: появятся тема и черновик.
3. По очереди отправить `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`: появится сообщение о ручном разборе, тема и предыдущий черновик будут очищены.
4. Отправить обычный текст ещё раз: помощник снова выдаст ответ.
5. Остановить сервер после открытия страницы и отправить заявку: текст останется, появится предложение разобрать её вручную.

Кнопка блокируется на время запроса. Изменение текста очищает результат и отменяет текущий запрос. Номер запроса дополнительно защищает от позднего ответа. У браузерного запроса есть отдельный лимит 2 секунды на случай недоступности сервера. Текст ответа выводится через `textContent`.

## Польза

Менеджер тратит меньше времени на определение темы и первый вариант ответа. При сбое он видит, что заявку нужно разобрать самому, и не примет старый черновик за новый. Эффект можно измерить по среднему времени обработки заявки с учётом проверки и правок.

Для реализации и проверки использован Codex.
